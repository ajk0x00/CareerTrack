# Experience Log Model and CRUD API

**Date**: 2026-10-13

## 1. Changes Made
- `app/models/experience_log.py`: Created SQLAlchemy model `ExperienceLog` mapped to `experience_logs` with `company_name`, `description`, `user_id` foreign key with cascade deletion, and timezone-aware timestamps.
- `app/models/__init__.py`: Re-exported `ExperienceLog`.
- `app/schemas/experience_log.py`: Created Pydantic schemas (`ExperienceLogBase`, `ExperienceLogCreate`, `ExperienceLogUpdate`, `ExperienceLogResponse`) with whitespace trimming and validation.
- `app/schemas/__init__.py`: Re-exported experience log schemas.
- `app/api/v1/endpoints/experience_logs.py`: Implemented authenticated CRUD API endpoints:
  - `GET /api/v1/experience-logs`: Lists experience logs for current user, supports substring filtering by `company_name`, sorted by `created_at DESC`.
  - `POST /api/v1/experience-logs`: Creates a new experience log for current user (`201 Created`).
  - `GET /api/v1/experience-logs/{id}`: Retrieves an experience log by ID with user isolation (`404` for unauthorized/missing).
  - `PATCH /api/v1/experience-logs/{id}`: Updates company name and/or description.
  - `DELETE /api/v1/experience-logs/{id}`: Deletes an experience log (`204 No Content`).
- `app/api/v1/router.py`: Mounted `experience_logs.router` under `/experience-logs`.
- `alembic/versions/5cb37eeab91f_create_experience_logs_table.py`: Created and applied database migration for `experience_logs` table and indexes.
- `alembic/env.py`: Added `include_object` filter to ignore supplementary legacy tables (`work_logs`, `tags`, `log_tags`) during autogenerate and schema checks.

## 2. Why the Change Was Made (Rationale)
- The user requested a model and CRUD API for Experience Log with company name and description fields to record work experience and accomplishments.
- Designed with user-scoped isolation and standard RESTful conventions under `/api/v1/experience-logs`.
- Filtered supplementary tables in Alembic's configuration so autogenerated migrations exclusively manage core SQLAlchemy application entities without accidentally attempting to drop external legacy tables.

## 3. Things to Lookout for in Future Development
- **Database Migrations Prerequisite**: Run `alembic upgrade head` in production after pulling changes so the `experience_logs` table is provisioned.
- **Frontend Integration**: The frontend `ExperienceModal` can be hooked to these endpoints by replacing local mock state with calls to `/api/v1/experience-logs`.
